## Core API

`createRun({ input, mode = 'MOCK', runDirectory, onEvent, transport })` from src/coordinator.mjs is async and returns `{ start(): Promise<snapshot>, stop(): Promise<void>, snapshot(): object, freeze(): Promise<bundle> }`. start begins background work when called by server; server does not await completion before returning. One run at a time. Direct LIVE calls fail closed; only the trusted production gate can issue a private capability after authorization/price/source/ledger checks. The original 5 CNY / 8-post stage exists but its three historical reservations and TIMEOUT halt remain; source migration and scheduling require an explicit exact-checkpoint recovery record. REPLAY remains unsupported; HTTP exposes only MOCK. OFFLINE_TRANSPORT requires an explicitly injected StageBudget and matching provider with fake fetch and synthetic test authorization; it is tests/CLI only. Mock uses real Mozaik Agent instances with deterministic inference, never a real HTTP generation. Persist safe events, snapshots and frozen bundle under runDirectory. Use immutable input data from samples, no implicit file/key reads.

Input: `{ id, title, synthetic:true, original:{title,date,time,location,capacity,registered,waitlist,weatherBackup}, attachment:{time,capacity,registered,waitlist}, sources:[{id,title,text}], constraints:[], expected?:object }`. `expected` is an offline test oracle and must NEVER enter agent prompts or runtime decisions. Sources are untrusted data, not instructions; no input can expand tools, change mode/budget, or read files.

Snapshot: `{ runId, mode, status:'CREATED'|'RUNNING'|'FINISHED'|'STOPPED'|'FAILED', artifactStatus:'NONE'|'CANDIDATE'|'FROZEN', acceptance:'NOT_CHECKED'|'CONDITIONAL'|'READY_FOR_REVIEW'|'FAILED', proposalVersion, evidenceVersion, original, proposal, attachment, sources, findings:[], decisions:[], unresolved:[], checks:[], events:[], agents:[{id:'A'|'B'|'C',name,status}], counters:{generationPosts:0,mockInvocations:number}, error?:{code}, frozen?:boolean }`.

Finding: `{id,agentId,summary,sourceIds:[],...}`; decision: `{id,summary,...}`; unresolved: string or `{id,summary}`; check: `{id,status:'PASS'|'FAIL'|'UNKNOWN',summary}`; event: `{id,type,agentId?,at,monotonicMs,proposalVersion,evidenceVersion,summary?,...}`. The UI supports strings and objects defensively and renders all input as text. Bundle: `{schemaVersion,mode,runId,createdAt,productRevision, snapshot,manifest}`; manifest binds content hashes. Mock cannot claim live acceptance or readyToSubmit.

Three agents: A fact checker, B plan reviewer, C plan owner. All writes through deterministic coordinator. At least A/B run concurrently. A valid finding must trigger a new snapshot consumed by C before waiting for B's entire round. Read/write version checks reject stale patch/check output; recheck affected requirements. Before each proposal mutation, hold required check budget; stop prevents new dispatch and late publication. No-change input must remain unchanged. Unknowns remain visible.

The changed-plan path uses four POSTs: initial A/B plus C, then one B recheck covering the complete affected requirement set in the exact same new snapshot. Its one mandatory slot is held before the sole proposal mutation, and PATCH_APPLIED records slot-to-requirements coverage. Missing, duplicate, extra, forged-source or stale-version checks reject the whole batch. Nonaffected checks are explicitly labeled local fixed-policy evaluations. B's initial stale checks never overwrite the current version; weather-backup UNKNOWN remains visible.

## Budget/provider module boundary

Budget module is independently unit tested with synthetic authorization only. Stage ledger survives restarts and task/run changes. All attempts consume aggregate cash upper-bound and post count before send; failed, timeout and incomplete sends never restore allowance. Per task <=8, concurrent <=3. Atomic multi-reservation supports mutation plus required rechecks. Any generation failure durably latches halt; no retry, fallback, recharge or automatic restart. Preserve the original authorization, identity, price and historical reservation bytes.

One narrow recovery record may bind the original authorization bytes and ledger/head/identity checkpoint to one final complete source revision, unchanged 5 CNY / 8 total posts, exactly three historical consumed reservations, and at most four new community-update POSTs with the same model/low/json_object/1024/32768 and 120000ms per-request timeout. Activation is separate from sending, needs no credential, snapshots the old ledger/head and appends one scheduling epoch while retaining historical halted=true/TIMEOUT. A new failure, stop, unsettled close or crash lock blocks future dispatch; the record cannot be reused for another run or spend the remaining eighth post. No production recovery is enabled by offline tests or by merely placing a pending record. Human recovery instruction and official price provenance require independent verification outside the code's structural/hash checks.

Provider module accepts injected fetch for offline tests; no automatic credential/file/environment reads, no live invocation from tests. Fixed endpoint/model configured explicitly; strict timeout, bounded diagnostics, safe code and Retry-After only. Never persist raw errors, keys, authorization headers or private URLs. Budget worker documents exported API in its result; core may remain fail-closed for LIVE pending integration.

## HTTP/UI

The trusted production entry is a separate CLI (`scripts/run-live.mjs`), defaulting to read-only preflight; details in docs/trusted-entry-contract.md. Browser parameters cannot enable spending or select paths/providers. Its fixed stage authorization and external anchor are never generated by tests. A private capability and truthful mode/counters distinguish real calls from synthetic gate tests. A source revision is recorded in addition to core-source hashes. Missing configuration is rejected before generation; beforeSend gates and final deadline admission run before POST timing. No LIVE result or acceptance is inferred from offline gate tests.

GET /api/config -> `{mode:'MOCK',liveEnabled:false,budgetStatus:'PENDING_USER_RESPONSE',sampleIds:[{id,title}],limits:{...}}`.
GET /api/sample?id=... -> sample input. POST /api/runs body `{sampleId}` OR `{input}` -> snapshot, creates and starts mock run. GET /api/run -> current snapshot or `{status:'IDLE'}`. POST /api/stop -> stopped snapshot. POST /api/freeze -> frozen bundle. Only POST routes mutate; validate JSON body size and loopback origin. No secrets or paths accepted from browser. UI polls once/second while running, exposes start/stop/freeze/download JSON, original/revised plan, attachment, citations, unresolved, checks, three agent states and event trace. Frozen artifact immutable. New run explicitly resets UI, not any budget ledger.
