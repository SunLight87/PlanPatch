# PlanPatch interface design

The workspace is a precise, calm document-review tool. Preserve the PlanPatch name, Chinese content, green primary action and navy text vocabulary. The interface should make the current document and its changes the most prominent content.

Use a clean white reading surface over a light neutral canvas, a stable materials/control column, dark ink headings and one deep green accent for the primary action/selection. Avoid decorating every region as an identical card. Group source excerpts as flat divided rows; keep one principal comparison surface, subordinate source and trace sections. Remove decorative uppercase eyebrows and section numbers. Technical run metadata belongs in an accessible disclosure rather than a dashboard of metrics.

Typography: one local sans stack, Microsoft YaHei UI/Microsoft YaHei/PingFang SC/system sans. Body and document values 15–16px, labels/helper copy >=13px, section titles 18–22px, page title 28–32px. No remote fonts. Fixed rem scale, normal Chinese tracking, tabular numeric values. Use spacing tokens based on 4px; 24–32px between groups, 12–16px within them.

Desktop: two-column workspace, roughly 280–320px materials column with remaining space dedicated to review. Header remains compact. Compare view leads; metadata/technical limits support. Native disclosures may reduce secondary noise but all substantive results remain visible/findable. Mobile: single column with controls before results; comfortable touch controls, wrapping labels, locally scrollable tables without page overflow. Breakpoints include 320,390,768,1024,1440.

Every state retains text labels. MOCK and unavailable LIVE are explicit without a warning-sized hero. The zero displayed count refers to this local demo run. Preserve all source anchors, event details, unknowns and frozen-export feedback. SVG strokes may illustrate actions; no emoji/Unicode pseudo-icons. Subtle 150–200ms control transitions, reduced-motion support, strong keyboard focus and text contrast.

This is a visual refinement of the existing task, not a change to backend behavior or evidence status. Current product source will have a new revision; historical 49afeb3b LIVE and recordings remain their original artifacts.
